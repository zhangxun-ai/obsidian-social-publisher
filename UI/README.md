## 统一设计

采用 Obsidian 浅色桌面界面：原生文件栏、紧凑表格与表单、淡灰分隔线、少量紫色交互强调。主导航仅有作品、处理记录、设置。以作品内容和图序为中心，不加入分析仪表盘或未来平台空页面。

[可复用提示词](prompts-v1.md) 包含共用视觉约束与每页完整提示词。

## 原型必须遵守的交互约定

- 工作台全选只包含当前筛选结果；切换筛选时，隐藏条目不得进入当前执行范围。无选择禁用动作；数量始终与本次范围一致。
- 保存编辑与确认本次发布内容是不同动作。任何正文、图序或图片字节变化使此前预览失效。
- 首图是封面；设为封面只调整顺序并去重。移除图片关联不删除原文件。候选图片不会自动加入。
- 新建只创建用户指定作品的最少文件。旧稿原位登记，保留已有属性；混合笔记默认没有正文范围，必须明确选择后才能登记和准备。06 导入图展示的是用户已经选择“发布正文”后的状态。
- 预览展示转换后的准确提交文本。无法可靠转换的结构逐项提示，缺失文件、失效章节、重复 ID 阻止准备。
- 07–09 为后续辅助填写与恢复流程的**状态设计**。原型只做模拟；正式实现本地 MVP 时不冒充已连接浏览器。
- 队列串行。当前作品未处理完不导航下一篇。停止仅停止剩余任务，不能撤回已发生的操作。
- 用户手工报告“已保存”或“已提交”先进入待核实；只有核对证据后才能升级对应结果。填写、平台草稿、发布、审核和可见性分别保存。
- 账号是本地核对标识，不代表已登录。原创与候选话题需在官方编辑器确认。
- 平台草稿保存、直接发布尚未验证，不提供可用动作。未接入或能力不支持时，展示原因与可行动的下一步。

## 关键状态补充

首次使用与零结果、导入尚未选章节、缺图、预览过期、源文件变更、停止队列、浏览器关闭、提交结果待核实均在原型中覆盖。图像无需为每个相同布局另建页面；状态由以上约定定义，不依赖 GPT Image 自动推导。
