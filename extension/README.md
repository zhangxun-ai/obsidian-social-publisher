# 配套 Chrome 扩展（实验适配）

此目录可在 Chrome 的“管理扩展程序”中选择“加载已解压的扩展程序”。它只接受 Obsidian 插件已准备并确认的版本；不会读取 Cookie，不调用平台私有发布接口，不点击发布、草稿或原创控件。

1. 在 Obsidian 确认准确的正文、账号与图片顺序，并将选中的作品准备为浏览器任务。手动启动浏览器桥接。
2. 在扩展中填写插件显示的端口和本次配对码，点击“配对并读取待填写作品”。配对码只保存在 Chrome 当前会话，不同步到云端。插件停止后旧码立即失效；重启后需重新配对。
3. 用户自行在 `https://creator.xiaohongshu.com/publish/publish` 打开一个空白图文编辑器。扩展不会导航、登录或切换账号。
4. 在扩展中选择一篇，核对账号和空白编辑器后领取填写。期间保持扩展窗口打开。首图按确认顺序作为封面；话题只是已经包含在正文中的文字，仍需人工完成平台关联。
5. 核实官方网页的全部图片和文案、账号、话题及原创声明。结果只记录“结果待核实”等辅助状态；本地记录不证明平台草稿已保存或已发布。
6. 处理当前网页后，在 Obsidian 明确确认本篇已处理，才可领取下一篇。已经领取的任务无法再次领取。窗口关闭、网络中断或结果不明时不会自动重试。

DOM 适配仅完成合成页面回归验证，尚未在用户已登录的真实小红书页面验收。页面结构不匹配时会停止，保留人工处理；上传完整性、平台保存和真实发布均未验证。不要将此适配视为平台授权或账号安全承诺。

桥接只监听 `127.0.0.1`，校验 Host、扩展来源、会话码和配对的扩展 ID。没有任意路径、文件读取或命令接口；每次领取和读取图片都重新核对已确认的源版本。清除配对不撤销已领取任务，需要回 Obsidian 核实。

Chrome MV3 的扩展 GET 请求不带 Origin。扩展因此使用空 JSON 的 POST 读取元信息和图片，让 Chrome 生成真实扩展 Origin；桥接仍严格拒绝缺失或非扩展来源，不信任自定义“扩展来源”头。带真实扩展 Origin 的 GET 读取接口同时保留。
