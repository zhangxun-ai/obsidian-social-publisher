# 配套浏览器扩展（实验适配）

面向用户的安装入口：[添加到浏览器](https://zhangxun-ai.github.io/obsidian-social-publisher/browser-extension.html)。0.1.4 已通过审核并发布，2026-10-09 已核实真实商店页面显示“添加至 Dia”。在要使用的 Dia 或 Chrome 中打开安装页并确认添加即可。公开分发的更改正在等待审核，现有不公开版本可通过链接安装。以下加载源码步骤仅用于开发测试。商店提交包、真实条目 ID 和提交记录见 [上架材料](../docs/store-listing.md)。

支持 Chrome 116 或以上。工作台通过 `chrome.runtime.getContexts` 查找自身页面并复用，不请求读取所有浏览标签页的 `tabs` 权限。

此目录可在 Chrome 的“管理扩展程序”中选择“加载已解压的扩展程序”。它只接受 Obsidian 插件已准备并确认的版本；不会读取 Cookie，不调用平台私有发布接口，不点击发布、草稿或原创控件。

1. 在当前 Dia 或 Chrome 登录小红书官方后台，在目标 Obsidian 知识库的「平台与账号」点击 **复制连接码**。这一步会自动开启本地连接。
2. 打开扩展工作台，粘贴连接码，点击 **连接并检测账号**。默认端口无需修改，自定义端口在「连接设置」中填写。配对码只保存在当前浏览器会话，插件停止后旧码立即失效。
3. 连接成功自动检测账号。仅检测你选择的官方标签页；同窗口一个官方页时自动选择，多个时明确选择。回 Obsidian 核对昵称并确认绑定；检测不会自动绑定。更换网页账号后可在扩展点击 **重新检测**。仅在工作台开启并配对期间回应检测，不在后台读取页面。
4. 核对正文与图片顺序、创建填写任务，再自行在 `https://creator.xiaohongshu.com/publish/publish` 打开空白图文编辑器，并在扩展工作台选择该标签页。
5. 在扩展中选择一篇，核对账号和空白编辑器后领取填写。期间保持扩展工作台标签页打开。首图按确认顺序作为封面；话题只是已经包含在正文中的文字，仍需人工完成平台关联。
6. 核实官方网页的全部图片和文案、账号、话题及原创声明。结果只记录“结果待核实”等辅助状态；本地记录不证明平台草稿已保存或已发布。
7. 处理当前网页后，在 Obsidian 明确确认本篇已处理，才可领取下一篇。已经领取的任务无法再次领取。窗口关闭、网络中断或结果不明时不会自动重试。

账号检测只向官方创作后台当前页面同源发送固定 GET `/api/galaxy/user/info`，使用浏览器本身的登录会话，验证 HTTP 成功、`success === true`、`code === 0`，仅返回公开 `data.userId` 与 `data.userName`；ID 必须为 24 位十六进制，昵称必须非空。不读取或导出平台 Cookie、密码、token 或平台 storage，不保存完整响应，不将可修改的小红书号、昵称或头像当作稳定 ID。请求超时、未登录、跳转、业务错误或身份不完整时停止。

2026-10-08 在用户登录的真实官方发布页完成只读验证：已观察页面本身的上述 GET，请求契约与字段形状核对通过；实际运行 `account.js` 检测返回 recognized，输出严格限定三个字段（状态、公开 ID、昵称）。验证过程仅记录形状和布尔结果，无个人账号值进入仓库。账号绑定交互与图片上传仍须分别验证，不将此只读结果当作真实上传、保存草稿或发布通过。图文填写适配仅完成合成页面回归验证。

领取任务前、选择图片前、等待上传后填写文字前，分别实时请求核对账号 ID；不使用旧检测缓存代替当下身份。页面结构不匹配时会停止，保留人工处理；上传完整性、平台保存和真实发布均未验证。不要将此适配视为平台授权或账号安全承诺。

桥接只监听 `127.0.0.1`，校验 Host、扩展来源、会话码和配对的扩展 ID。没有任意路径、文件读取或命令接口；每次领取和读取图片都重新核对已确认的源版本。清除配对不撤销已领取任务，需要回 Obsidian 核实。

Chrome MV3 的扩展 GET 请求不带 Origin。扩展因此使用空 JSON 的 POST 读取元信息和图片，让 Chrome 生成真实扩展 Origin；桥接仍严格拒绝缺失或非扩展来源，不信任自定义“扩展来源”头。带真实扩展 Origin 的 GET 读取接口同时保留。
