## 长描述（可复制到商店）

把已经在 Obsidian 中整理和确认的图文，交给小红书官方编辑器继续核对，减少重复复制文案和选择图片。

本扩展需要配套的 Social Publisher 桌面 Obsidian 插件，不能独立管理知识库。首次使用，请先安装插件，再开启本地连接，在扩展工作台中输入插件显示的端口和配对码。

使用方式：
1. 在同一个浏览器中手动登录小红书官方创作后台。
2. 在扩展工作台选择要操作的官方标签页，回 Obsidian 检测并核对账号，明确确认绑定。
3. 在 Obsidian 选择发布正文和图片，检查完整预览并创建填写任务。
4. 自行打开小红书官方空白图文编辑器，在扩展中核对账号、确认编辑器为空，然后领取一篇作品并辅助填写。
5. 在官方网页逐项检查图片、文案、账号、话题和原创声明，自行决定是否发布。

扩展会核对公开账号 ID，账号不一致、页面无法识别或编辑器已有内容时停止操作。首图按用户确认的顺序作为封面。已领取的任务不会自动重发，填写结果仅记录为“结果待核实”等辅助状态。

账号登录由官方网页完成。扩展借助浏览器现有登录会话向固定的官方同源地址读取账号 ID 和昵称，不读取或导出 Cookie、密码、平台 token 或平台存储。配对信息仅存于当前浏览器会话；文案、图片和账号检测信息通过本机回环连接在扩展与 Obsidian 插件之间传递，不发送到开发者服务器。

点击辅助填写后，图片会交给官方网页，可能由平台上传；文字填入官方编辑器后也可能由平台自动保存。平台如何处理这些内容遵循平台自身规则。

当前小红书填写适配属于实验功能。真实平台图片上传完整性、平台保存草稿和公开发布尚未完成验收。扩展不会点击发布、保存草稿或原创声明控件，也不代表平台官方授权。请始终在官方网页核实结果。微信公众号和 X 当前不支持。

## 单一用途说明（开发者后台）

配合 Social Publisher 桌面 Obsidian 插件，把用户明确确认的图文内容辅助填写到其选择的小红书官方空白图文编辑器；为避免填错账号，仅检测并核对该官方页面的公开账号身份。账号检测、本地配对和任务结果回传均服务于这一图文填写流程。

## 权限理由（开发者后台）

| 权限 | 目的与实际范围 |
| --- | --- |
| `scripting` | 在用户选择的 `creator.xiaohongshu.com` 官方标签页执行随扩展打包的账号检测与填写脚本；读取固定账号接口的公开字段，检查编辑器是否为空，选择已确认图片并写入文案。没有远程托管脚本。 |
| `storage` | 使用 `chrome.storage.session` 保存本机连接端口及本次配对码，仅限当前浏览器会话；不使用同步存储，不保存平台登录凭据。 |
| `http://127.0.0.1/*` | 连接用户手动开启的本机 Obsidian 插件服务，完成配对、读取已准备任务及图片、回传账号检测与填写结果。端口由用户输入；服务校验回环地址、Host、扩展来源及配对码。此权限不用于访问开发者服务器或局域网其他设备。 |
| `https://creator.xiaohongshu.com/*` | 在扩展工作台列出当前窗口该官方域名的标签页供用户选择，并在所选页面检测账号；只在 `/publish/publish` 路径的空白编辑器辅助填写。账号检测是固定的同源 GET `/api/galaxy/user/info`，由浏览器处理其现有登录会话，仅保留公开账号 ID 与昵称。不会读取一般网站页面。 |

扩展不请求 `activeTab`、`tabs`、`history` 或 `cookies` 权限。对官方页面的访问仅由上述固定站点权限授权；列出该站点标签页仍会处理有限的 URL、标题和标签页 ID，详见以下隐私披露。

远程代码说明：执行脚本均随扩展打包。固定官方账号接口返回 JSON 数据，不将响应当作脚本执行。扩展不下载或执行远程代码，不使用动态代码生成来运行服务器提供的逻辑。

## 隐私实践填写依据

应披露“为实现功能而处理的数据”，不能把“没有开发者服务器”填写成“完全不处理任何用户数据”。以下按当前实现列出；后台字段名称以提交时版本为准。

| 数据 | 实际处理及去向 | 商店数据分类填写建议 |
| --- | --- | --- |
| 小红书公开账号 ID、昵称、检测时间 | 从用户选中的官方页面识别，经本机连接回传插件。用户确认绑定后，插件保存在当前知识库插件数据中，并用于核对任务账号。 | 身份识别信息；明确这是公开平台账号标识和昵称，不是开发者收集真实姓名或邮箱。 |
| 发布标题、正文、图片、图片文件名及类型、账号备注、任务标识与结果 | 插件仅把用户确认的任务交给扩展。扩展在内存中处理并填写官方页面；图片交给网页后可能上传，文案可能由平台自动保存。结果返回插件，本地保留任务记录。 | 网站内容 / 用户提供的内容。填写权限用途和隐私说明须涵盖文本、图片与账号信息的传输。 |
| 所选官方标签页的 URL、标题和标签页 ID | 工作台列出当前窗口的官方创作后台页面，用来选择、定位并校验目标；不读取全站历史记录，不上传开发者。 | 若后台以访问页面 URL、标题定义“网络浏览记录”，应按该有限范围披露并选中，不因不读历史数据库而笼统否认。 |
| 本地端口、本次配对码 | 用户输入，存于浏览器会话存储，随请求发送给本机插件授权通信；可在扩展清除，插件停止连接即使旧码失效。 | 若后台把令牌、授权码纳入“身份验证信息”，应选中并说明仅是本机插件配对码。不能把“不提取平台 Cookie”扩大成“不处理任何授权信息”。 |

没有支付、健康、定位或通信采集功能，不主动从这些来源读取数据；用户选择的文案图片仍可能自行包含个人信息，因此不能笼统声称从不处理敏感内容。无分析、广告、数据出售或开发者服务器接收。官方平台本身的登录与内容处理属于其自身服务；本扩展仍需披露其发起的账号检测及用户内容填写行为。

可以根据实际行为确认：数据仅用于上述单一用途；不出售用户数据；不为广告或与该用途无关的目的使用、转移数据；不用于信贷或借贷评估。提交者必须核对当期表单条款与全部勾选项。

## 给审核者的操作说明

测试需要桌面 Chrome 116 或以上、桌面 Obsidian 1.14.4 或以上，以及可以自行登录的小红书创作后台账号。扩展不提供或接收测试密码；开发者不共享私人登录会话。如果审核者无法访问平台，请联系 GitHub Issues 说明测试障碍，不能以伪造的账号或演示结果代替实际审核。

1. 在一个独立测试知识库安装并启用 Social Publisher 插件。插件安装入口及 BRAT 前置步骤见主页；这是另一个独立安装项，扩展安装不会代装 Obsidian 插件。
2. 在插件「平台与账号」开启本地连接。打开扩展工作台，输入插件显示的端口和本次配对码，点击「配对并读取待填写作品」。保持工作台标签页打开。
3. 在同一个浏览器窗口手动登录 `https://creator.xiaohongshu.com/`，在扩展刷新并选择该官方标签页。回插件点击「检测登录状态」，核对公开账号信息并确认绑定。此时可验证：登录网站本身不自动绑定，确认绑定前插件不保存绑定关系。
4. 在测试知识库创建一篇合成发布内容，使用简短测试文案及一张自己拥有的测试图片。给作品选择已绑定账号，查看完整预览并确认，创建填写任务。不要使用个人知识库或敏感素材。
5. 自行打开 `https://creator.xiaohongshu.com/publish/publish` 的空白图文编辑器，在扩展选择该官方标签页，重新配对读取任务，选择测试作品，勾选账号及空白编辑器核对项，再点击填写按钮。
6. 检查官方页面与插件结果。扩展仅尝试填写，结果需人工核实；不要点击发布。可以改用有现成文字的编辑器验证“停止且不覆盖”，或在浏览器换账号验证账号不一致时停止。
7. 测试结束，关闭本地连接，并清除扩展中的配对信息。官方平台已经接收到的图片或自动保存内容由审核者依平台界面自行处理，扩展不声称可以撤销平台上传。

审核范围说明：当前实现没有最终发布操作，也没有自动保存草稿操作。账号检测是登录后固定同源 GET；只有在已配对工作台保持打开时，才响应 Obsidian 发起的短期检测请求。后台 Service Worker 只负责打开/复用工作台，不在后台轮询或注入页面。
